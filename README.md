# 党考复习助手 · gduf-dangyuan-exam-coach

一个面向高校党校党考的备考教练技能：用历史题库统计高频考点，按剩余天数制定冲刺计划，带练单选、多选、填空、简答，维护错题闭环，生成模拟卷与押题排序，并附带一个完全离线的单文件刷题页。

- 适用：入党积极分子结业考、发展对象/预备党员考试（后者为重点）。
- 形态：Qoder Agent Skill + 离线 HTML 刷题页 + Markdown/JSON 预测卷。
- 数据：381 道历史题，归并为 346 个题组，覆盖 18 个主题。
- 原则：高频优先、以题带点、主动回忆、间隔重复、输出倒逼输入。
- 边界：题库不是官方题库，考试结构是按题库推断的，押题不承诺命中。

仓库地址：<https://github.com/9zqzh/gduf-dangyuan-exam-coach>

## 这个项目解决什么问题

党考备考通常有三个难点：

1. **范围大、时间少**：党章、党史、二十大报告、三中/四中全会、纪律处分条例、时政都可能考，但考前只剩几天。
2. **不知道重点**：同一道题在不同年份、不同题型里反复出现，靠通读材料很难看出哪些是高频。
3. **会看不会写**：客观题能认出来，简答却写不出骨架；错题看一遍答案就放过，下次仍然错。

这个项目把历史题库变成一套可执行的冲刺系统：

- 先统计“哪些考点反复考”，把时间压在高频题组上。
- 再用“诊断 → 计划 → 串讲 → 带练 → 错题回炉 → 模考 → 考前 24 小时”的流程推进。
- 对话里一次只练一道、讲一道，适合考前碎片时间。
- 离线刷题页负责重复训练、计时模考和数据记录。
- 所有结论都能追溯到 `assets/` 下的数据文件，不凭记忆报数字。

它不替代系统学习，也不提供所谓“内部题”。它的价值是：在有限时间里，把最可能拿分的地方先拿下。

## 快速开始

### 方式一：作为 Qoder Skill 使用（推荐）

把仓库放进 Qoder 的个人技能目录。Windows 本机路径为：

```text
C:\Users\<用户名>\.qoder-cn\skills\
```

克隆（Git Bash / macOS 用 `~`，Windows CMD 用 `%USERPROFILE%`）：

```bash
cd ~/.qoder-cn/skills
git clone https://github.com/9zqzh/gduf-dangyuan-exam-coach.git
```

目录结构应为：

```text
C:\Users\<用户名>\.qoder-cn\skills\gduf-dangyuan-exam-coach\SKILL.md
```

然后在会话里直接描述需求即可，例如：

- “我 7 天后考发展对象，每天 1 小时，怎么安排？”
- “先带我过一遍高频考点。”
- “开始刷题，一次一道。”
- “给我一套押题卷。”
- “这道题为什么错？”
- “讲讲全过程人民民主，考试会怎么问？”
- “我简答写不出来，教我模板。”

技能被触发后，会先读 `assets/config.json`、`assets/stats.json`、`assets/高频知识点报告.md`、`assets/corrections.json` 和 `reference/` 下的策略文件，再按流程推进，不凭记忆报数字。

如果会话没有自动触发，检查两点：

1. 目录名是否为 `gduf-dangyuan-exam-coach`。
2. `SKILL.md` 顶部的 `name` 是否与目录名一致。

### 方式二：只打开离线刷题页

仓库里已经构建好单文件页面：

```text
assets/党考刷题.html
```

双击用 Chrome、Edge、Firefox 或 Safari 打开即可。页面不依赖服务器、不加载 CDN、不发起网络请求，断网也能用。

Windows 命令行打开：

```bash
start "" "assets\党考刷题.html"
```

macOS：

```bash
open "assets/党考刷题.html"
```

### 方式三：直接读预测卷

三套卷子都有 Markdown 和 JSON 两种格式：

```text
assets/预测卷_A.md   assets/预测卷_A.json
assets/预测卷_B.md   assets/预测卷_B.json
assets/预测卷_C.md   assets/预测卷_C.json
```

- Markdown 适合阅读、打印、转成 Word/PDF。
- JSON 适合二次开发、导入其他刷题工具或做数据分析。

## 第一次使用：10 分钟上手

### 第 1 步：做一次诊断

从题库抽 10 道单选 + 3 道多选 + 2 道填空，限时 10 分钟，不查资料。记录：

- 正确率。
- 错题属于哪个主题。
- 错因是“没学过”还是“见过但选不准”。

### 第 2 步：确认考试信息

至少确认 5 件事：

1. 考哪种：积极分子结业 / 发展对象 / 预备党员。
2. 考试日期或剩余天数。
3. 每天能投入多少分钟。
4. 当前基础：没学过 / 看过一遍 / 做过题 / 模拟过。
5. 最担心什么：客观题、简答、时政、记不住、时间不够。

这些信息写入 `data/profile.json`。可以从示例复制（Git Bash / macOS 用 `cp`，PowerShell 用 `Copy-Item`）：

```bash
cp data/profile.example.json data/profile.json
```

`data/profile.json` 是本地个人档案，已在 `.gitignore` 中排除，不会进入 Git。

### 第 3 步：先排 3 天，不要一次排满

按剩余天数套模板，先排最近 3 天，做完再滚动更新。每天最多安排 80% 的可用时间，剩下 20% 留给错题和突发情况。

### 第 4 步：用刷题页建立手感

打开 `assets/党考刷题.html`：

1. 先点“高频专练”，做 20—40 题。
2. 再点“错题重练”，把刚错的题回炉。
3. 考前 3 天用“模拟考试”卡一次 90 分钟。

### 第 5 步：把错题变成一句话

每道错题只做三件事：

1. 标原因：知识盲区 / 概念混淆 / 审题失误 / 表述不熟 / 时政过时。
2. 写正确表述：一句话，不抄整段。
3. 安排回炉：第 2、4、7 天各一次；连续 3 次答对才移出。

## 详细功能指南

### 1. 首次诊断

诊断的目的不是打分，而是决定接下来把时间花在哪。

建议题量：

| 题型 | 题量 | 目的 |
|---|---:|---|
| 单选 | 10 | 看再认能力和常见挖坑 |
| 多选 | 3 | 看固定表述是否成体系 |
| 填空 | 2 | 看能否准确回忆固定表述 |

诊断后分三类处理：

- **知识盲区**：完全没见过。回到主题框架，补一个知识块，不要继续盲目刷题。
- **概念混淆**：两个相似表述选错。做两列对比表，只记差异。
- **表述不熟**：知道意思但写不出。背关键词和句式，不背整段。

### 2. 制定冲刺计划

按剩余天数选择策略：

| 剩余时间 | 策略 | 目标 |
|---|---|---|
| 3 天以内 | 只保高频 + 错题 + 两套卷 | 客观题 70%+，简答有骨架 |
| 7 天 | 高频串讲 + 分题型突破 + 3 套模拟 | 稳定 75 分 |
| 14 天 | 高频 + 全主题覆盖 + 错题闭环 | 稳定 80 分 |
| 30 天 | 系统学习 + 每周模考 + 时政更新 | 85 分以上 |

7 天模板：

| 天数 | 主任务 | 产出 |
|---|---|---|
| D1 | 诊断 + 高频主题 1（二十大/中国式现代化） | 一张框架图，20 题 |
| D2 | 高频主题 2（党史）+ 单选专项 | 错题清单，30 题 |
| D3 | 高频主题 3（经济/高质量发展）+ 多选专项 | 易混对比表，30 题 |
| D4 | 党章党规 + 填空专项 | 固定表述清单，40 空 |
| D5 | 简答模板 + 4 道简答默写 | 4 篇骨架答案 |
| D6 | 整套模拟考 A + 逐题复盘 | 分数与失分原因表 |
| D7 | 错题回炉 + 高频速览 + 早睡 | 只看错题和框架 |

每日 90 分钟样板：

```text
00—05  回顾昨日错题（3—5 题）
05—35  新主题串讲：框架 → 3 个考点 → 1 个易混点
35—60  对应练习 20—25 题，即时看解析
60—75  错题回炉：写错误原因 + 正确表述
75—85  简答默写 1 题（只写骨架）
85—90  今日 3 句话总结
```

计划要留缓冲：每天最多安排 80% 的可用时间。连续两天状态差时，减少新内容，只做错题回炉。

### 3. 高频考点串讲

从 `assets/stats.json` 取主题排序，优先讲前 3—5 个。当前快照前五：

1. 党的二十大与中国式现代化
2. 党史与党的奋斗历程
3. 经济建设与高质量发展
4. 习近平新时代中国特色社会主义思想
5. 党的领导与政治建设

每个主题用“3+1”结构：

1. **一句话框架**：这个主题在考什么。
2. **三个必考点**：原文表述 + 考试问法 + 一个例子。
3. **一个易混点**：和相邻概念的区别。
4. **一道自测题**：讲完立刻问，等待回答。

教学原则：

- 先问后讲：先让用户复述已知，再补缺口。
- 一次只讲一个知识块，讲完立刻自测。
- 多用对比表，少用长段背诵。
- 区分“再认”（看到能选）和“回忆”（闭卷能写）；简答必须练回忆。
- 讲完让用户用 3 句话总结，不能复述就说明没掌握。

### 4. 带练与仿题库出题

#### 用现成题库带练

从 `assets/bank.json` 按主题/题型取题。一次只发一道：

```text
【单选】题干……
A. ……
B. ……
C. ……
D. ……
```

用户作答后再给：

- 正确答案与原文依据。
- 为什么错：知识盲区 / 概念混淆 / 审题 / 表述不熟。
- 一句话记忆锚点。
- 如果题库答案存疑，先说明，再给官方表述。

不建议一次发 10 道再统一对答案。考前突击更需要碎片化反馈。

#### 仿原题库风格出新题

用户要“再出几道”时，按以下规则：

- 题干长度、问法、选项风格贴近原题库；优先用固定表述和会议原文。
- 单选 4 个选项，只有 1 个最佳答案；多选 4 个选项，2—4 个正确项。
- 干扰项要“像真的”：同主题、同层级、同句式，避免一眼假。
- 正确项分布均衡，不要连续多题同一个字母。
- “以上都对/以上都不对”不超过 10%。
- 不出有争议的时政数字；不确定就不出。
- 每题附：答案、考点、易错点、依据。

出题后做两遍校验：

1. 答案是否唯一、是否与原文一致。
2. 干扰项是否真的错、题干是否有歧义。

### 5. 简答专项

先让用户写骨架（定性句 + 3—5 个分点），再看参考答案。反馈只做三件事：

- 缺了哪个采分点。
- 哪个表述不准确。
- 哪句话可以删掉。

不替用户写完整答案；给骨架和关键词，让用户自己展开。

简答按“骨架 + 展开”答题：

1. **定性句**：是什么 / 地位作用。
2. **分点**：3—5 点，每点一个关键词开头。
3. **落脚句**：意义 / 要求 / 怎么做。

10 分题建议写 4—6 个要点，每点 1—2 句。不会时也不要空：写出定义、主体、目标、要求，通常能拿到 3—5 分。

简答训练法：

1. 只看题目，用 3 分钟写骨架。
2. 不看答案，口头复述一遍。
3. 对照参考答案，补缺失的关键词。
4. 把答案压缩成 5 个关键词，第二天只看关键词复述。
5. 一周后随机抽 2 题，限时 8 分钟重写。

### 6. 错题回炉

错题不是“看一遍答案”，而是走完三步：

1. **标原因**：知识盲区 / 概念混淆 / 审题失误 / 表述不熟 / 时政过时。
2. **写正确表述**：一句话，不抄整段。
3. **安排回炉**：第 2、4、7 天各一次；连续 3 次答对才移出。

HTML 刷题页会自动记录错题：

- 练习中答错，立即加入错题本。
- 之后每次答对，`streak` 加 1；连续答对 3 次，自动移出。
- 模拟考答错也会加入；但模拟考答对不会直接增加回炉连击，仍需在练习模式里完成 3 次正确。
- “错题重练”按错误次数排序，错得多的先练。

回炉时不要只问“答案是什么”，要问“为什么其他选项错”。能讲清干扰项，才算真会。

### 7. 模拟考

#### 网页模拟考

进入“模拟考试”，选择 60/90/120 分钟，点击开始。默认按题库推断的结构组卷：

| 题型 | 题量 | 分值 | 小计 |
|---|---:|---:|---:|
| 单项选择 | 30 | 1 | 30 |
| 多项选择 | 10 | 2 | 20 |
| 填空 | 10 | 1 | 10 |
| 简答 | 4 | 10 | 40 |
| 合计 | 54 | — | 100 |

考试特性：

- 从题库按主题轮转抽题，同一题组不重复。
- 计时到 0 自动交卷；提前交卷会提示未答题数。
- 单选、多选、填空自动判分；简答交卷后对照参考答案自评。
- 答题卡显示已答/未答，可直接跳题。
- 交卷后生成总分、客观题得分、简答自评、用时和分项表。
- 可逐题回顾，查看你的作答、正确答案、参考答案和“答案存疑”提示。
- 可导出 Markdown 格式的考试报告。
- 可“只练错题”，把本次错题加入错题本并直接进入重练。

判分规则：

- 单选：唯一答案完全一致才得分。
- 多选：集合完全一致才得分，少选、多选、错选均不得分。
- 填空：按空逐一比对，整题所有空都正确才得该题满分，不设部分分。
- 简答：自评 0/2/4/6/8/10，按采分点给分，不按字数给分。

#### 纸笔模拟考

直接用 `assets/预测卷_A/B/C.md`，限时 90 分钟，不查资料。流程：

1. 交卷后先看总分，再看分项：单选/多选/填空/简答。
2. 只复盘三类题：错题、蒙对的题、超时题。
3. 简答按采分点自评 0/2/4/6/8/10。
4. 生成“失分原因表”，下一轮只改最影响分数的两项。

分数段建议：

| 分数 | 下一步 |
|---|---|
| 80+ | 保持手感，主攻简答表述和时政更新 |
| 60—79 | 客观题补高频，简答补骨架 |
| 40—59 | 回到高频主题串讲，暂停刷新题 |
| 40 以下 | 先做主题框架，不要盲目刷题 |

### 8. 押题

用户说“押题”时，输出：

1. 高频题组 TOP 10（来自 `stats.json`）。
2. 每个题组的“可能问法”：单选/多选/填空/简答各一句。
3. 三套卷的定位：A 高频核心、B 均衡覆盖、C 补漏冲刺。
4. 一句边界：按频率排序，不保证命中，时政以官方最新为准。

不使用的表述：“必考”“内部题”“今年一定考”。不把预测卷包装成真题。

### 9. 答疑

回答结构：

1. **结论**：一句话直接答。
2. **依据**：原文/文件/会议，给可点击来源。
3. **易错点**：最容易混的 1—2 个点。
4. **考试怎么考**：单选/多选/填空/简答的可能问法。

规则：

- 先查 `assets/corrections.json`，看是否题库本身有误。
- 题库答案与官方原文冲突时，明确说“题库这条存疑”，给官方表述，不静默改答案。
- 时政、数字、会议届次不确定时，先检索再答；检索不到就说不知道。
- 不编造文件号、日期、讲话出处；引用控制在一两句。
- 来源优先级见 `reference/teaching-sources.md`。

来源优先级从高到低：

1. 党章、二十大报告、三中全会《决定》、四中全会文件、纪律处分条例、习近平总书记讲话原文。
2. 中国政府网、共产党员网、新华社、人民日报、求是网、中央党校、中央党史和文献研究院。
3. 人民网党建频道、光明网政治频道（适合背景梳理，具体表述回到原文）。
4. 地方党组织、高校党校公开学习材料（只用于理解框架，不作为最终依据）。

不使用自媒体解读、营销号“押题秘籍”、无法追溯出处的截图。

### 10. 背景教学

用户要“讲讲背景/串一下历史”时，按主题而不是按时间线堆砌。推荐模块：

- 党史时间轴：建党 → 新中国成立 → 改革开放 → 新时代。
- 理论体系：马列主义 → 毛泽东思想 → 邓小平理论 → “三个代表” → 科学发展观 → 习近平新时代中国特色社会主义思想。
- 党章党规：性质宗旨、党员义务权利、组织制度、纪律处分。
- 时政：二十大、二十届三中全会、二十届四中全会、“十五五”。

20 分钟小课模板：

```text
2 分钟  问题导入：为什么现在强调这个？
5 分钟  框架：时间/逻辑/关键词
8 分钟  三个考点 + 一个易混对比
3 分钟  自测：3 道题或 1 个复述
2 分钟  小结：3 个词
```

背景教学也要落到考试：每个背景点最后加一句“考试可能怎么问”。

## 离线刷题页详细说明

文件：`assets/党考刷题.html`（约 356 KB，单文件，无外部依赖）。

### 打开方式

- 双击文件，用浏览器打开。
- 或从命令行打开（见“快速开始”）。
- 不需要安装、不需要服务器、不需要联网。
- 手机上使用：把 HTML 文件传到手机，用浏览器打开即可。

### 六种模式

| 模式 | 行为 | 适合场景 |
|---|---|---|
| 顺序练习 | 按题型（单选→多选→填空→简答）和题号排序 | 第一遍系统过题 |
| 随机练习 | 打乱顺序 | 防止记住位置 |
| 高频专练 | 按加权分和出现次数排序，默认取前 40 题 | 考前优先拿重复分 |
| 错题重练 | 只练错题本中的题，按错误次数排序 | 每天开始前的回炉 |
| 模拟考试 | 按结构组卷、计时、交卷、报告 | 考前卡时间 |
| 学习数据 | 累计作答、正确率、学习天数、主题掌握度、薄弱主题、词云、最近模考 | 每周复盘 |

“高频专练”的题量上限来自 `assets/config.json` 的 `analysis.high_freq_question_count`（当前 40）。不是题库只有 40 道高频题，而是默认只取排序最前的 40 道。

### 筛选与搜索

- 题型：全部 / 单选 / 多选 / 填空 / 简答。
- 主题：18 个主题下拉筛选。
- 搜索：题干和答案文本，支持关键词，例如“中国式现代化”“纪律处分”。
- 清除筛选：一键回到全部题目。
- “单选点击后立即判题”：默认开启；关闭后需要点“提交”再判题，适合想先想清楚再看的场景。

筛选条件会作用于顺序、随机、高频、错题四种练习模式；模拟考试按自己的组卷逻辑抽题，不受当前筛选影响。

### 答题与反馈

- **单选**：点击选项；开启即时判题时立即出结果。
- **多选**：选择多个选项后提交；少选、多选、错选都算错。
- **填空**：题干中的 `__1__`、`__2__` 会渲染成输入框；提交后逐空标出对错，整题全部空正确才算答对。
- **简答**：输入答案后提交，对照参考答案自评；反馈会给出参考答案、题组频率、主题，以及“答案存疑”提示（如果该题在 `corrections.json` 中）。
- 每题反馈包含：正确答案、原文/参考答案、题组出现次数、主题、存疑提示。
- 答错会自动加入错题本。

### 收藏与快捷键

- 收藏按钮，或按 `F`：收藏/取消收藏当前题。
- 数字键 `1`—`4`：选择对应选项。
- `Enter`：下一题 / 提交填空。
- 收藏数量显示在左侧“今日状态”和顶部统计中。

### 模拟考试细节

- 时长可选 60/90/120 分钟，默认 90。
- 题量结构由 `assets/config.json` 的 `exam.blueprint` 决定；默认 30+10+10+4。
- 抽题时优先覆盖高权重主题，同一题组不重复。
- 计时最后 5 分钟会变成警示色。
- 时间到自动交卷；手动交卷时若有未答题，会二次确认。
- 交卷后客观题立即出分，简答题需要手动自评。
- 报告包含：总分、客观题得分、简答自评、用时、分项得分、逐题回顾。
- 可导出 Markdown 报告，文件名形如 `党考模拟报告_YYYY-MM-DD.md`。
- 可“只练错题”，把本次错题加入错题本并进入重练。

### 学习数据

“学习数据”页包含：

- 累计作答数、正确率、学习天数、错题本数量。
- 主题掌握度：按作答记录计算每个主题的正确率，优先显示最薄弱的 10 个。
- 薄弱主题：正确率低于 80% 的前 5 个主题，可一键“练这个主题”。
- 高频词云：来自 `stats.json` 的前 24 个高频词。
- 最近 5 次模拟考：日期、用时、总分。

练习记录最多保留最近 6000 条，模拟考记录最多保留最近 60 次。

### 数据保存、导出与导入

数据保存在当前浏览器的 `localStorage`，键前缀为 `dangyan_v1_`：

| 键 | 内容 |
|---|---|
| `dangyan_v1_wrongbook` | 错题本（错误次数、连击、最后作答、你的答案） |
| `dangyan_v1_favorites` | 收藏 |
| `dangyan_v1_history` | 练习记录 |
| `dangyan_v1_exam_history` | 模拟考记录 |
| `dangyan_v1_settings` | 即时判题、考试时长等设置 |

操作：

- **导出进度**：下载 JSON，包含 `version`、`exportedAt`、`wrongbook`、`favorites`、`history`、`examHistory`、`settings`。
- **导入**：选择之前导出的 JSON，覆盖当前浏览器的错题、收藏、练习记录和模考记录；导入前会二次确认。
- **重置**：清空错题本、收藏、练习记录和模考记录；会二次确认。

注意事项：

- 换浏览器、换电脑、清理浏览器缓存前，先“导出进度”。
- 用 `file://` 打开时，不同浏览器对本地存储的隔离策略可能不同；如果发现进度“消失”，先确认是否换了浏览器或文件路径。
- 无痕/隐私模式关闭后可能清空数据。
- 页面不联网，也不会上传任何作答记录。

### 打印

页面内置打印样式：

- 浏览器 `Ctrl+P`（macOS `Cmd+P`）。
- 打印时自动隐藏顶栏、侧边栏、答题导航和按钮，只保留题目/报告主体。
- 适合打印错题清单、模拟考报告或预测卷页面。

### 移动端

- 页面有响应式布局，窄屏下侧边栏和题目区会重排。
- 已在 524px 宽度下检查过无横向溢出。
- 手机上打开需要先把 HTML 文件传到手机；不需要服务器。
- 手机浏览器也可以使用 localStorage 保存进度，但换浏览器同样会丢，重要进度先导出。

## 三套预测卷

每套 54 题，满分 100，建议 90 分钟：

| 卷子 | 定位 | 组卷倾向 | 适合谁 |
|---|---|---|---|
| A 卷 | 高频核心 | 优先高频题组，覆盖最常考的主题 | 时间紧、先保基本盘 |
| B 卷 | 均衡覆盖 | 按主题轮转，尽量覆盖 18 个主题 | 已过一遍、需要查漏 |
| C 卷 | 补漏冲刺 | 偏向低频但覆盖盲区，补 A/B 没覆盖到的点 | 已完成 A/B、想再扫盲区 |

每套卷包含：

- 30 道单选（每题 1 分）。
- 10 道多选（每题 2 分）。
- 10 道填空（每题 1 分）。
- 4 道简答（每题 10 分）。
- 答案与说明：题组频次、主题、加权分、存疑提示。
- 免责声明：按频率排序，不是命题预测，不保证命中。

使用建议：

1. 第一套用来暴露问题，不要追求高分。
2. 第二套重点看“同一个考点换问法”是否还会。
3. 第三套只在前两套复盘完成后做，否则只是重复焦虑。
4. 每套做完必须做“失分原因表”，否则刷卷的收益很低。

### 统计口径

- **近重复题组**：题干字符二元组 Jaccard 相似度 ≥ 0.72，或短题干被长题干包含且长度比 ≥ 0.8。
- **题组**：同一考点的不同问法；`count` 是题组内题目数，`weight` 是加权分。
- **加权频次**：单选 1.0、多选 1.2、填空 1.1、简答 1.4；含 2026/2025/2024 或“十五五/二十届四中全会”的题额外加权。
- **主题统计**：主主题计全权重，次要主题计 0.25 权重。
- **题组代表题**：优先选文本更完整、题型更“重”的题。
- **高频词**：按“出现在多少个题组”排序，括号内为覆盖题组数。

### 数据质量

- 答案主要从 docx 红字提取；选择题红字可能标在字母上，也可能标在选项正文上。
- 原文有 8 处下划线空格在 docx 中丢失，已按上下文补回“（ ）”标记，答案未改。
- 选择题均有 4 个选项，答案键有效；解析待复核为 0。
- 超长填空答案 0 道；过短简答答案 0 道。

## 数据格式

### bank.json

顶层：

```json
{
  "meta": {
    "version": 1,
    "generated_at": "2026-10-31T22:07:16",
    "sources": [{"file": "选择题题库.docx", "count": 187}],
    "counts": {"single": 122, "multi": 65, "fill": 140, "short": 54},
    "total": 381,
    "needs_review": 0,
    "schema": "dangyan-bank-v1"
  },
  "questions": []
}
```

单题：

```json
{
  "id": "single-1a2b3c4d",
  "type": "single",
  "section": "single",
  "number": 12,
  "stem": "题干（填空用 __1__ 标记空位）",
  "options": [{"key": "A", "text": "..."}],
  "answer": ["B"],
  "answer_text": "原始答案文本",
  "blanks": ["习近平", "李强"],
  "topic": "congress20",
  "topic_name": "党的二十大与中国式现代化",
  "tags": ["congress20", "thought"],
  "source": "选择题题库.docx",
  "order": 11,
  "needs_review": false,
  "review_reason": ""
}
```

字段说明：

- `answer` 只对选择题有意义；`blanks` 只对填空题有意义；`answer_text` 三种题型都保留。
- `id` 由题型 + 归一化题干生成。题干改动会导致 id 变化，`corrections.json` 的 id 需要同步检查。
- `needs_review` 为 `true` 时，该题不会进入模拟考抽题池；刷题页仍会显示，但会标注待复核。

## 重建与维护

### 依赖安装

```bash
python -m pip install python-docx
```

Windows 建议设置 UTF-8 输出，避免中文乱码。

Git Bash / macOS / Linux：

```bash
export PYTHONIOENCODING=utf-8
```

PowerShell：

```powershell
$env:PYTHONIOENCODING="utf-8"
```

### 一键重建

在项目根目录依次运行：

```bash
PYTHONIOENCODING=utf-8 python scripts/build_bank.py
PYTHONIOENCODING=utf-8 python scripts/analyze.py
PYTHONIOENCODING=utf-8 python scripts/make_exam.py
PYTHONIOENCODING=utf-8 python scripts/build_trainer.py
```

顺序不能乱：

1. `build_bank.py` 解析 docx，生成 `assets/bank.json`。
2. `analyze.py` 读取题库和主题，生成 `assets/stats.json` 和 `assets/高频知识点报告.md`。
3. `make_exam.py` 读取题库、统计、配置，生成三套预测卷。
4. `build_trainer.py` 把题库、统计、配置、存疑条目注入模板，生成 HTML。

如果只想更新页面（例如改了 `corrections.json`），只跑第 4 步即可。

### 脚本参数

| 脚本 | 参数 | 说明 |
|---|---|---|
| `build_bank.py` | `--input` | 题库目录或单个 docx，默认 `assets/source/` |
| | `--output` | 输出路径，默认 `assets/bank.json` |
| `analyze.py` | `--bank` | 题库路径 |
| | `--taxonomy` | 主题配置路径 |
| | `--config` | 考试/分析配置路径 |
| | `--out-dir` | 输出目录，默认 `assets/` |
| | `--top` | 报告展示的主题数，默认 15 |
| `make_exam.py` | `--paper` | `A` / `B` / `C` / `all`，默认 `all` |
| | `--out-dir` | 输出目录，默认 `assets/` |
| | `--bank` / `--stats` / `--config` / `--taxonomy` | 覆盖默认输入 |
| `build_trainer.py` | `--out` | 输出 HTML 路径，默认 `assets/党考刷题.html` |
| | `--title` | 页面标题 |
| | `--bank` / `--stats` / `--config` / `--corrections` / `--taxonomy` | 覆盖默认输入 |

示例：

```bash
# 只生成 B 卷
PYTHONIOENCODING=utf-8 python scripts/make_exam.py --paper B

# 输出到自定义位置
PYTHONIOENCODING=utf-8 python scripts/build_trainer.py --out "D:/党考刷题.html"

# 从自定义题库目录解析
PYTHONIOENCODING=utf-8 python scripts/build_bank.py --input "D:/题库" --output "assets/bank.json"
```

### 新增题库

1. 把新的 docx 放进 `assets/source/`。
2. 确认文件名与 `build_bank.py` 中的路径匹配，或使用 `--input` 指定目录。
3. 运行 `build_bank.py`，检查输出中的“待复核”数量。
4. 抽查 10—20 题：题干、选项、答案、填空空位。
5. 运行 `analyze.py`、`make_exam.py`、`build_trainer.py`。
6. 如果新增了主题，先更新 `taxonomy.json`，再重建。

解析规则要点：

- 题号支持 `1、` `1.` `1．`，也处理题号与题干粘连（如 `78一切从实际出发`）。
- 选项支持 `A、` `A.` `A．`，也支持题干内联选项、缺首字母、无字母连续选项。
- 正确答案用红色字体标注，可能标在选项字母上，也可能标在选项正文上。
- 填空答案从红色/下划线片段提取；空位在题干中用 `__1__` 表示。
- 简答题题干后紧跟“答：”或参考答案段落。
- 解析异常会写入 `needs_review` 与 `review_reason`；正常应为 0。

### 修改考试结构

编辑 `assets/config.json` 的 `exam.blueprint`，保持字段名 `type`、`count`、`points`、`name`：

```json
{
  "blueprint": [
    {"type": "single", "count": 30, "points": 1, "name": "单项选择题"},
    {"type": "multi", "count": 10, "points": 2, "name": "多项选择题"},
    {"type": "fill", "count": 10, "points": 1, "name": "填空题"},
    {"type": "short", "count": 4, "points": 10, "name": "简答题"}
  ]
}
```

改完后至少重跑：

```bash
PYTHONIOENCODING=utf-8 python scripts/make_exam.py
PYTHONIOENCODING=utf-8 python scripts/build_trainer.py
```

如果改了主题或统计参数，再跑 `analyze.py`。

注意：

- `total_points` 应与 `count × points` 的总和一致。
- 题量不能超过题库中该题型的可用题数，否则会组不满。
- 当前 HTML 只实现了单选、多选、填空、简答四种题型；新增判断题、辨析题、案例分析需要改解析器、组卷逻辑和页面渲染，不是只改配置就能完成。

### 更新存疑条目

1. 编辑 `assets/corrections.json`，补充 `id`、`type`、`number`、`severity`、`issue`、`suggestion`、`source`。
2. 运行 `build_trainer.py` 重新生成页面。
3. 如果 `id` 因题干改动而变化，先用 `bank.json` 查到新 id。
4. 不要直接改 `bank.json` 里的答案；保留原始提取结果，把修正写在 `corrections.json`，便于追溯。

- [ ] 简答题有参考答案，无明显截断。

## 设计原则

1. **高频优先**：先把反复考的主题吃透，再补冷门。
2. **以题带点**：每道错题都要回到知识点，而不是只记答案。
3. **主动回忆**：合上答案复述，比反复看讲义有效。
4. **间隔重复**：当天、第 2 天、第 4 天、第 7 天各回炉一次。
5. **输出倒逼输入**：简答先写骨架，再对照参考答案补漏。
6. **一次只推进一个阶段**：诊断、计划、串讲、带练、回炉、模考，不一次倒出全部功能。
7. **先问后讲**：先让用户复述已知，再补缺口。
8. **可追溯**：所有数字来自 `assets/`，不凭记忆；与官方冲突时明确标注存疑。
9. **不制造焦虑**：计划留缓冲，每天只设一个主任务，完成就收工。

## 常见问题

### 1. 这是官方题库吗？

不是。它是对历史题库的整理和统计，用于训练和模拟。真实考试范围以本单位通知和官方教材为准。

### 2. 押题能押中吗？

不能保证。押题的本质是按历史频率排序，告诉你“哪些考点更值得先看”。它不预测具体原题，也不承诺命中。

### 3. 考试结构和真实考试不一样怎么办？

修改 `assets/config.json` 的 `exam.blueprint`，让题量、分值、总分与通知一致，然后重跑 `make_exam.py` 和 `build_trainer.py`。如果真实考试有判断题、案例分析等新题型，当前解析器和页面不支持，需要二次开发。

### 4. 为什么题库有 381 道，高频专练只有 40 道？

高频专练默认只取加权排序前 40 道，数量由 `analysis.high_freq_question_count` 控制。你可以把它调大，或在筛选里按主题练。

### 5. 多选怎么判分？少选给分吗？

不给。多选必须与答案集合完全一致才得分，少选、多选、错选都算错。这是为了贴近多数党考的多选规则；如果本单位有特殊规则，需要改页面判分逻辑。

### 6. 填空是逐空给分吗？

练习模式下会逐空标出对错，但整题需要全部空正确才算答对。模拟考中填空每题 1 分，全部空正确才得 1 分，不设部分分。

### 7. 简答怎么自评？

按采分点自评 0/2/4/6/8/10，不按字数。先看定性句是否准确，再看分点是否齐全，最后看表述是否规范。报告里的“简答自评”会计入总分。

### 8. 刷题进度存在哪里？会上传吗？

存在当前浏览器的 `localStorage`，键前缀 `dangyan_v1_`。页面上传不了数据，也没有云端。换浏览器、换电脑或清缓存前，先“导出进度”。

### 9. 手机上能用吗？

能。把 `assets/党考刷题.html` 传到手机，用浏览器打开即可，不需要服务器。手机上的进度同样存在该浏览器里，换浏览器会丢。

### 10. 可以打印吗？

可以。浏览器 `Ctrl+P` / `Cmd+P`，页面会自动隐藏侧边栏和按钮。适合打印错题清单、模拟考报告。

### 11. 为什么有的题显示“答案存疑”？

因为该题在 `assets/corrections.json` 中被标记为存疑、笔误或过时。页面只提示，不自动改答案；考试时优先按官方原文作答。

### 12. 题库答案和官方原文冲突，听谁的？

听官方原文。答疑会明确说“题库这条存疑”，给出官方表述和来源，并保留题库原答案以便追溯。不要把存疑条目直接改成“看起来对”的答案而不留记录。

### 13. 时政题会过时吗？

会。题库包含 2025/2026 时政内容，会议届次、数字、表述都可能随政策更新。考前用中国政府网、共产党员网、新华社等官方来源复核。

### 14. 可以新增题库吗？

可以。把 docx 放进 `assets/source/`，运行 `build_bank.py`，检查待复核数量，再依次跑 `analyze.py`、`make_exam.py`、`build_trainer.py`。详细规则见 `reference/data-and-rebuild.md`。

### 15. 为什么仓库里没有原始 docx？

原始 docx 的文档属性可能包含作者姓名等元数据，公开仓库不适合收录。`assets/bank.json` 已包含解析后的题库，统计、组卷、页面构建都能直接重跑；只有“从 docx 重新解析”需要自备源文件。

### 16. 可以二次开发吗？

可以。题库、统计、配置都是普通 JSON；页面是单文件 HTML + 原生 JavaScript；脚本是 Python。你可以替换题库、改考试结构、改页面样式，或把 JSON 导入自己的刷题工具。仓库暂未附带 LICENSE，公开分发前请先联系作者确认授权。

### 17. 为什么计划只排 3 天？

因为考前计划最容易“排得很满、执行不了”。先排 3 天，做完再滚动更新，能根据实际进度调整，也能留出错题和突发情况的时间。

### 18. 每天时间很少，先做什么？

先做高频专练 + 错题回炉，不要从第一页开始通读。时间少于 30 分钟时，只做 10 道高频题 + 3 道错题；时间 60 分钟时，按“20 题 + 回炉 + 1 道简答骨架”安排。
